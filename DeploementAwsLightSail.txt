Deployment Overview
The NesterConversationalBot runs on an AWS Lightsail instance in the ap-south-1 (Mumbai) region using a lightweight, containerized setup.​

AWS Lightsail Instance
Plan: 7 USD/month Lightsail instance

Specs: 1 GB RAM, 2 vCPUs, 40 GB SSD, 2 TB data transfer included​

Region: ap-south-1 (Mumbai) for low latency to Indian users and simple pricing.​

Lightsail is used because it provides predictable monthly cost, bundled data transfer, and a simpler experience than managing raw EC2 for small apps.​

Core Tools and Setup
Docker (Containerization)
Docker is installed on the Lightsail instance to package the entire application stack into containers, making deployments reproducible and easy to manage.​

Install steps (after SSH):

bash
# SSH into instance
ssh -i ~/LightsailKey.pem ec2-myIP

# Install Docker
sudo yum install -y docker git
sudo systemctl start docker
sudo systemctl enable docker
sudo usermod -aG docker ec2-user
Docker Compose (Orchestration)
Docker Compose is used to start all services (API, WebSocket, static files, etc.) with a single command, simplifying deployment and updates.​

bash
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" \
  -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose
Networking and Caddy
Lightsail Networking
Region: ap-south-1 (Mumbai)

Static IP: attached to the instance

Firewall ports opened: 22, 80, 443, 7860, 8765 for SSH, HTTP/HTTPS, and app services.​

Caddy (Reverse Proxy + HTTPS)
Caddy is an open-source web server used as a reverse proxy in front of the containers. It automatically provisions and renews SSL certificates via Let’s Encrypt and handles HTTP to HTTPS redirection.​

Install Caddy:

bash
sudo yum install -y caddy
Configure Caddy with a nip.io domain:

bash
sudo tee /etc/caddy/Caddyfile << EOF
YOUR_IP.nip.io {
    handle /connect* { reverse_proxy localhost:7860 }
    handle /status*  { reverse_proxy localhost:7860 }
    handle /ws       { reverse_proxy localhost:8765 }
    handle { 
        root * /var/www/nester
        try_files {path} /index.html
        file_server
    }
}
EOF
Start Caddy:

bash
sudo systemctl enable caddy
sudo systemctl start caddy
This gives you HTTPS termination, path-based routing, and a cleaner public endpoint with minimal configuration.​

Deploying the Application
Upload Code
bash
rsync -avz --exclude 'venv' --exclude 'node_modules' . ec2-user@YOUR_IP:~/nester-bot/
Deploy with Docker Compose
bash
cd ~/nester-bot
cp env.example .env    # Fill in API keys and config
docker-compose up -d --build
From this point, the stack can be updated by re-rsyncing the code and running docker-compose up -d --build again.

Cost and Capacity Overview
Monthly Infrastructure Cost
Lightsail instance (1 GB): 7 USD/month

Static IP: free when attached

Data transfer: 2 TB included

Storage: 40 GB SSD included

SSL certificates (Let’s Encrypt via Caddy): free​

Total infrastructure: about 7 USD/month for the base server.

Estimated API Costs (Example: ~100 Conversations/Day)
Deepgram STT: around 50 minutes/day → roughly mid–single-digit USD/month at current per‑minute rates​

Deepgram TTS: around 100k characters/day → low–single-digit USD/month​

OpenAI GPT‑3.5: around 500k tokens/day → a few USD/month at current per‑1k‑token pricing​

Combined, API usage for moderate traffic is roughly 14 USD/month, so total monthly cost is around 21 USD/month for infrastructure plus APIs.

Capacity and Upgrade Path
The 7 USD plan is suitable for roughly 15–20 concurrent users for a real-time conversational bot, based on typical CPU and memory needs for small web workloads.​

Higher Lightsail plans (for example 12–15 USD/month tiers with more RAM and SSD) are available if more concurrency or heavier models are needed.

Connection Flow (Step by Step)
User opens https://3.6.64.48.nip.io/

Caddy serves the static frontend and handles HTTPS.​

User clicks “Connect” in the UI

The frontend sends a POST /connect request to the backend.

The backend responds with a WebSocket URL like wss://3.6.64.48.nip.io/ws.

Frontend opens the WebSocket

It connects to wss://3.6.64.48.nip.io/ws.

Caddy proxies this WebSocket connection to the backend on port 8765.
